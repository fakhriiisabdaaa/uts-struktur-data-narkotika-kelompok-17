ADR 001: Pemilihan Struktur Data Utama dan Sekunder
Tanggal: 4 November 2026
Pengambil Keputusan: Fakhri Sabda Lazuardi (002), Marsciano Tri Julian (025)

1.	Konteks
Program ini dibuat untuk mengelola 50 data putusan narkotika yang diekstrak ke CSV, dengan beberapa fitur seperti menampilkan, menambah, menghapus, mencari, memfilter, dan mengurutkan data. Dalam pembuatan program ini, struktur utama dilarang menggunakan library dari java langsung, sehingga harus membuat struktur utama secara mandiri. 

2.	Keputusan
Kami memutuskan struktur utama dan sekunder sebagai berikut:
  1.	Array Dinamis (Utama)
 Sebagai struktur data utama untuk menyimpan data putusan Ketika brogram dijalankan. Dibuat menggunakan Object[] dengan kapasitas awal 26. Jika kapasitas awal penuh, ukurannya akan bertambah 2 kali lipat.
  2.	Stack (Sekunder)
Sebagai struktur data tambahan untuk menyimpan Riwayat aktivitas. Stack menggunakan prinsip LIFO, sehingga aktifitas terakhir dapat ditampilkan terlebih dahulu.

3.	Alasan Pemilihan
Array Dinamis dipilih karena memudahkan pengaksesan data berdasarkan indeks dan sesuai dengan kebutuhan fitur aplikasi. Sementara itu, Stack dipilih karena riwayat aktivitas lebih mudah ditampilkan berdasarkan urutan terbaru. Kami juga mempertimbangkan untuk menggunakan Linked List, tetapi Array Dinamis dirasa lebih sesuai karena aplikasi membutuhkan akses data berdasarkan indeks.

4.	Konsekuensi
Penggunaan Array Dinamis memudahkan pengelolaan data, tetapi penghapusan data di tengah array membutuhkan proses pergeseran elemen. Sementara itu, Stack memiliki keterbatasan karena penghapusan hanya dapat dilakukan dari bagian paling atas.
Meskipun demikian, kedua struktur data tersebut sudah cukup untuk memenuhi kebutuhan aplikasi.
